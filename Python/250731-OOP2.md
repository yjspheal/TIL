## 메서드 오버라이딩 vs 오버로딩

### 내용

**오버라이딩 (Method Overriding)**
- **상속** 관계에서 부모 클래스의 메서드를 **같은 이름, 같은 파라미터**로 재정의하는 것  
  → 자식이 부모의 기능을 "내 입맛대로" 바꾸는 개념
- **Python**: 공식적으로 지원

**오버로딩 (Method Overloading)**
- 같은 클래스 내에서 **이름은 같지만 파라미터 구성(개수/타입)이 다른 메서드를 여러 개 정의**  
  → 같은 이름의 함수를 다양한 방식으로 호출할 수 있게 함
- **Python**: 공식적으로 미지원 (마지막에 정의된 함수만 남음)

| 구분       | 오버라이딩                   | 오버로딩                         |
|------------|------------------------------|----------------------------------|
| **목적**   | 부모 메서드의 동작 수정      | 같은 이름의 메서드를 다양하게 사용 |
| **범위**   | 상속(다른 클래스)            | 클래스 내부(같은 클래스)         |
| **Python** | 지원                         | 미지원                          |

## 메서드 오버라이딩 시 주의할 점

### 내용

- 오버라이딩을 할 때는 **이름과 파라미터 구조를 반드시 부모와 똑같이 맞춰야** 한다.
- Python에서는 파라미터 구조가 달라도 에러가 발생하지 않지만, **다형성(polymorphism)**이 깨지고 예기치 않은 에러를 초래할 수 있다.
  - 다형성이란?
    - 어떤 객체의 속성이나 기능이 상황에 따라 여러가지 형태를 가질 수 있는 성질을 의미

### 예시

```python
class Animal:
    def eat(self):
        print("Animal이 먹는 중")

class Dog(Animal):
    def eat(self, food):  # ⚠️ 잘못된 오버라이딩
        print(f"Dog가 {food}를 먹는 중")

def feed_animal(animal):
    animal.eat()

dog = Dog()
feed_animal(dog)  # TypeError 발생
